# Contributing

Thank you for helping improve this knowledge base. Useful contributions include
reproducible prompt techniques, model observations, explanations of conditioning
behavior, and corrections to existing material.

## Writing requirements

- Use descriptive, lower-case, hyphen-separated filenames.
- Use Markdown headings in order: a single `#` title, `##` main sections, and
  `###` subsections. Do not skip heading levels.
- Keep explanations direct and readable by screen readers.
- All submissions must follow semantic heading structures and avoid visual
  ASCII diagrams. Do not use box-drawing characters or emoji-heavy decoration.
- Explain equations and technical relationships in plain descriptive English;
  do not rely on complex raw LaTeX.
- Label examples and state when syntax is illustrative rather than supported by
  every model or interface.

## Technical observations

When possible, identify the model or interface, relevant settings, the prompt
or conditioning method, the observed result, and whether the result was
repeatable. Distinguish direct observations from hypotheses. Avoid presenting a
model-specific behavior as universal.

Do not include private data, credentials, copyrighted lyrics, or material you
do not have permission to share. When discussing a result, describe the
relevant musical qualities instead of reproducing protected source material.

## Submitting changes

Use the issue template for a prompt technique or model observation. For
documentation changes, keep the scope focused, verify internal links, and
preserve the existing accessible structure. Clarify limitations and
uncertainties rather than implying that a prompt guarantees a specific output.

## Licensing

By submitting original documentation, you agree that it may be distributed
under the repository's Creative Commons Attribution 4.0 International license.
If you include third-party material, identify its source and license and make
sure redistribution is permitted.
